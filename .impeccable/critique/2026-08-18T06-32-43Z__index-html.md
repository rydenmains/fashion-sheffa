## Overall Impression

The batik identity problem is solved — this now feels like a real batik house, not a template. The remaining risks are robustness and polish around the edges: content hidden behind JS, a WhatsApp share preview that may not render, and accessibility gaps a shop's phone-using customers will hit. The single biggest opportunity: make the page fully legible and shareable without a single line of JavaScript, since the primary traffic arrives via WhatsApp/social links.

## What's Working

1. **The design system is now the brand.** Kawung motif, dye-bath palette, crop-mark frames, and mono metadata carry batik identity without a single photo doing all the work. The `-webkit-text-stroke` outline line on the hero and the rust marquee are the kind of authored moves that read as deliberate.
2. **Conversion architecture is right.** WhatsApp is reachable at every scroll position: hero CTA ("Chat WhatsApp" names the action), fixed bottom-right FAB (52px, thumb zone), footer socials with real platform labels + handles. This directly serves the stated job (tap WhatsApp to trust + buy).
3. **Motion discipline.** 420ms ease-out, 16px rise, 80ms stagger, transform/opacity only, `prefers-reduced-motion: reduce` fully disables everything including the marquee. Respects the lite-first constraint.

## Priority Issues

- **[P1] Whole page is invisible without JS.** `.reveal`, `.product`, and `.hero__line`/`.hero__sub`/`.btn--wa` all start `opacity: 0` in `style.css:436-445, 249-253, 619-628` and only appear when `main.ts` runs `inView`/`animate`. No `<noscript>` fallback. If the ~27KB motion bundle fails, is blocked, or is slow on mobile data, the user sees a hero title, a marquee, and blank sections. This is a lite-first mobile site whose entire job is being viewable — the page must render without JS.
  - **Why it matters:** The worst-case visitor (Surakarta phone user on 2G, JS blocked by data saver) sees an empty shop and leaves. Undermines the core promise.
  - **Fix:** Set `.reveal`/`.product` visible by default and only hide them when JS confirms animation is available (add a `js` class to `<html>` from `main.ts`, gate the hidden states behind `.js`), or add a `<noscript>` stylesheet that forces opacity 1. Then keep the entrance animation for the JS-enabled majority.
  - **Suggested command:** `$impeccable harden`
- **[P1] OG image is a relative path.** `<meta property="og:image" content="/membatik.webp">` at `index.html:13`. WhatsApp/TikTok/IG share crawlers (the site's stated primary traffic source, PRODUCT.md) fetch that path against their own origin, so the link preview almost certainly shows no image or a broken one.
  - **Why it matters:** The store's reach depends on share links looking trustworthy. No preview image = flat, grey, anonymous share bubble = fewer taps through.
  - **Fix:** Absolute URL `https://<domain>/membatik.webp` (build-time or in-source), plus `og:url` + `og:image:width/height` for a clean card. Verify with a crawler test.
  - **Suggested command:** `$impeccable harden`
- **[P1] h1 doesn't name the brand.** The single `h1` is the English "BATIK FASHION" (`index.html:59-62`); "Fashion Sheffa" lives in `hero__sub` as a `<p>`. The brand name appears nowhere in heading structure.
  - **Why it matters:** Screen readers (Sam) and search engines read the h1 as the page's identity. "Batik Fashion" is a category, not the shop. Hurts both SEO and first-timer orientation.
  - **Fix:** Make the h1 "Fashion Sheffa" (or "Fashion Sheffa — Batik") and keep "BATIK/FASHION" as the outlined display treatment via aria-hidden or move it to a styled `<p>`. Don't lose the visual moment — restructure the semantics, not the look.
  - **Suggested command:** `$impeccable clarify`
- **[P2] Lightbox has no focus management.** `show()`/`closeLightbox()` in `main.ts:124-146` move no focus in on open, trap no focus while open, and restore nothing on close. Tab can walk behind the 98% scrim.
  - **Why it matters:** Keyboard + screen-reader users (Sam) can't browse photos linearly without losing the overlay; the Esc/arrow support that exists is only discoverable by accident for them.
  - **Fix:** On open, move focus to `.lightbox__close`; keep focus in the overlay with a minimal trap; on close, return focus to the triggering `.product` button.
  - **Suggested command:** `$impeccable harden`
- **[P2] Rust accent fails AA contrast on dark sections.** `#9c4a2f` on `#14203a` = **2.65:1** (WCAG AA needs 4.5:1 for normal text). Used in `.vm__no` (the `01`/`02` ledger numbers on the Visi-Misi ink section, `style.css:566-573`) and marquee `i` separators. `--accent-hi #b85c3a` on ink = 3.57:1, also failing.
  - **Why it matters:** The mono numbers are real content (mission items 01/02). On a low-brightness phone screen they wash out. This is exactly the "rust on indigo" combo the palette wants — it just needs a lighter rust on ink.
  - **Fix:** Add a dark-surface accent token (e.g. `#d97b55` ~4.6:1 on ink) for text on ink sections; keep `#9c4a2f` for borders/motifs. `--grey` (3.25:1 on paper) is also below AA and currently defined-but-unused.
  - **Suggested command:** `$impeccable audit`
- **[P2] Product names repeat with no differentiation.** `PRODUCTS` (`main.ts:6-15`) has "Daster" ×3 and "Tunik" ×2. Three identical-looking cards all labeled "Daster" reads as a rendering bug to a shopper; there's no variant (warna/ukuran/bahan), price, or craft grouping.
  - **Why it matters:** Primary job is "see what the store sells". Repeat labels without variant info force Casey/Jordan to guess or WhatsApp just to learn what's different. The prior run dropped prices (correct — no data); but the labels still need differentiation the owner can provide.
  - **Fix:** Ask Yulia for per-product variant lines (e.g. "Daster — motif cap", "Daster — motif tulis"), or group products by category (Batik / Craft) with subtitles. Never invent data.
  - **Suggested command:** `$impeccable clarify`
- **[P2] Mobile drawer: no Esc, no focus handling.** `.nav__links` drawer opens on toggle (`main.ts:26-34`) but there's no Esc-to-close, no focus moved into the drawer, and no backdrop, so tab focus can leak behind it.
  - **Why it matters:** Jordan/Keyb users get stuck with an open drawer; link-tap closes it (good) but keyboard users may not find that.
  - **Fix:** Esc closes the drawer; on open, focus the first link; aria-expanded is already managed — wire the rest.
  - **Suggested command:** `$impeccable harden`

## Persona Red Flags

**Jordan (confused first-timer)** — Landing page primary persona:
- h1 reads "BATIK FASHION" — English loan on an Indonesian page; the brand name "Fashion Sheffa" is a small mono line below it. Jordan has to assemble the identity from sub-label + nav.
- Nav says "Tempat" but the section title says "Lokasi Fashion Sheffa" — two words for the same destination, minor but adds a beat of doubt for a literal-minded first-timer.
- If JS is slow, the whole Tentang section is blank when they scroll to it — instant "broken shop" impression.

**Casey (distracted mobile user)** — Primary persona (this is a phone-first shop):
- FAB is correctly thumb-reachable (52px, bottom-right), hero CTA visible — good. But the 8 product cards are `opacity:0` until JS animates them; on a slow connection the grid appears card-by-card, and if the tab is backgrounded mid-load, `inView` may not fire until they scroll again.
- Three cards all named "Daster" — on a phone, scanning fast, reads as duplicate/broken grid.
- Share link preview (their actual entry point) likely shows no image because og:image is relative.

**Sam (accessibility-dependent)** — a11y issues concentrated here:
- No `:focus-visible` styling anywhere in `style.css` — every interactive element relies on the browser default ring, which is often invisible on the cream/ink backgrounds.
- Rust ledger numbers on ink at 2.65:1 — unreadable at normal size.
- Lightbox: no focus trap, no focus-in on open, no focus return on close.
- Positive: alt text present on every image, buttons (not divs) for all interactive cards, `aria-expanded`/`aria-controls` on the toggle, decorative rail/marquee/motif correctly `aria-hidden`.

## Minor Observations

- `--grey: #808080` defined at `style.css:9`, used nowhere; at 3.25:1 on paper it would fail AA anyway. Remove or fix.
- `.section__title { cursor: default }` (`style.css:414`) — headings aren't interactive; odd affordance.
- `hero__rail` vertical writing-mode was removed in favor of horizontal meta-bar — consistent with DESIGN.md.
- Ken Burns 16s on hero fabric is subtle and reduced-motion-safe; fine.
- Lightbox lacks a "3 / 8" position indicator; nice-to-have for a gallery.
- Footer giant watermark is `aria-hidden` — good decorative use of display type.
- `dist/` exists in the repo — a stale build could shadow `index.html` changes if anyone deploys from it.
